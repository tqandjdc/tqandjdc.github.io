iOS 越狱设备电子取证完全指南

一、概述

本文档面向电子数据取证人员，详细解析已越狱（Jailbroken）iOS 设备的文件系统结构。越狱后设备拥有完整的 root 权限，可访问原本受限的系统目录，这为取证提供了大量在传统非越狱设备上无法获取的数据。

二、iOS 文件系统根目录全解

iOS 基于 Darwin（Unix 内核），其文件系统结构沿袭了 Unix 的传统。以下按截图中的目录逐一说明，包含根目录层和各目录的核心子目录。

.Trashes 回收站（类似废纸篓） ★★ 可能有已删除文件恢复

2.2 为什么 var 和 etc 既在根目录出现又在 private 下？

这是理解 iOS 文件系统的关键点：

根目录的 /var 和 /private/var、/etc 和 /private/etc 本质上是同一个位置。 iOS 使用符号链接（symbolic link）让 /var 指向 /private/var，/etc 指向 /private/etc。这是 Unix 系统的常见做法。

取证时你应该走的路径是 /private/var/，因为这是完整路径，不会混淆。

七、取证注意事项

7.1 越狱判定依据

依据 路径/文件
Cydia 应用商店 /Applications/Cydia.app
MobileSubstrate 框架 /Library/MobileSubstrate/
Cydia 数据 /var/lib/cydia/、/var/lib/apt/
越狱标记文件 .cydia_no_stash、.installed_home depot
越狱 App 目录 /Applications/ 下有非标准 App

7.2 时间线分析

iOS 时间戳使用 Core Foundation Date：从 2001-01-01 00:00:00 UTC 开始的秒数。

注意： iMessage 和某些应用使用苹果历书时间（Apple Reference Date），从 2001-01-01 开始的纳秒，需要除以 10^9。

7.3 数据保护与完整性

  1. 哈希校验：提取数据后立即计算 SHA-256/MD5 哈希值
  2. 只读操作：取证过程中确保只读模式，避免修改原始数据
  3. 镜像备份：优先获取完整磁盘镜像（dd 或专业工具）
  4. 取证报告：记录所有提取的文件路径、哈希值、提取时间

7.4 加密数据

  • iOS 11+ 设备文件系统默认加密
  • 需要提取 UID 和 密钥链主密钥 才能解密
  • 完整取证通常需要设备解锁状态
  • Keychain 数据即使解密文件系统也无法直接读取

7.5 常见数据删除与恢复

  • SQLite 数据库删除后，若页面未被覆写，可使用 sqlite3 的 .recover 命令恢复
  • 照片删除后，PhotoData.sqlite 和 PhotosImports.plist 可能仍保留删除记录
  • 浏览器历史记录在缓存文件中可能保留残片
  • .bash_history 中的命令删除后，可通过磁盘扫描恢复

7.6 文件权限与所有者

  • iOS 文件权限遵循 Unix 传统
  • 普通用户文件所有者为 mobile，系统文件为 root
  • 越狱后可读取所有文件（包括受保护的目录）
