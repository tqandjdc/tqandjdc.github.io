平台层面是什么意思？SDK又是什么？

● SDK 是什么？

SDK = 软件开发工具包。就像你装了一台空调，空调厂家给的是整套空调系统。SDK

就是厂家给开发者的一整套工具，让开发者不用从头造轮子。

Bugly SDK 就是腾讯给 App 开发者的一整套代码库，开发者只需几行代码就能在自己的 App

里接入崩溃统计功能：

开发者集成 Bugly SDK

      ↓

App 崩溃了 → Bugly SDK 自动收集崩溃信息 → 上报到腾讯服务器

      ↓

开发者在 Bugly 后台看到：”今天有 5 个用户崩溃了，原因是什么”

“平台层面”是什么意思？

分两层理解：

App 层面（应用层）

每个 App 自己产生的数据，只跟这个 App 有关。比如虚拟定位应用崩溃时的崩溃报告。

平台层面（SDK 平台层）

SDK 作为一个中间平台，它自己维护的信息，不依赖于具体 App。

类比：

平台层面（Bugly 平台）

├── 设备指纹：03a81561-…（同一台设备，不管装什么 App，这个 UUID 都一样）

└── IP 地址：240e:410:120:…

应用层面（虚拟定位应用）

├── 崩溃记录：包名 com.lerist.fakelocation

├── 崩溃原因：java.lang.NullPointerException

└── 设备标识：c1f47f87-a33f-…（只有这个 App 上报的崩溃报告里才有）

所以”平台层面的设备指纹”意思是：Bugly 这个平台自己生成的设备标识，跟具体哪个 App

无关，用于跨应用识别设备。

平台层面的UUID就是一个手机的特定标识符？SDK是不是就相当于是底层框架

● 平台 UUID 是不是手机特定标识符？

不是手机硬件的唯一标识，是操作系统分配的。

Android 系统给每台设备分配了几个标识符：

┌──────────────────┬─────────────────────────────────────────────────────────────┐

│ 标识符 │ 特点 │

├──────────────────┼─────────────────────────────────────────────────────────────┤

│ IMEI │ 手机硬件唯一，但 Android 10+ 不允许 App 获取 │

├──────────────────┼─────────────────────────────────────────────────────────────┤

│ Android ID │ 应用重装或清数据后会变 │

├──────────────────┼─────────────────────────────────────────────────────────────┤

│ GAID │ 广告 ID，用户可以重置 │

├──────────────────┼─────────────────────────────────────────────────────────────┤

│ Bugly 生成的 │ Bugly 自己算出来的，基于设备信息哈希，跟 Android │

│ UUID │ 系统标识不同 │

└──────────────────┴─────────────────────────────────────────────────────────────┘

所以 03a81561-… 是 Bugly SDK 自己算出来的，不是手机出厂就有的。不同

SDK（友盟、Firebase）算出来的 UUID 不一样，但同一台设备上通常是固定的。

SDK 是不是底层框架？

不是。 SDK 是”工具箱”，底层框架是”地基”。

类比：

底层框架（Android 系统本身）

├── SQLite（数据库）

├── Network（网络）

└── …

SDK（第三方工具箱，你主动引入的）

├── Bugly SDK — 崩溃统计

├── 微信 SDK — 分享登录

└── 支付宝 SDK — 支付

你的 App（你自己写的代码）

  • 底层框架是 Android 自带的，所有 App 共享

  • SDK 是开发者自己选择引入的，像”插件”一样挂在你的 App 上

  • 同一个 App 可以集成多个 SDK，也可以一个都不集成
